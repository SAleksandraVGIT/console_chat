# Qt-клиент

Оконный интерфейс использует Qt Widgets 6.4+ и общий `ChatClient`. Он не обращается
к БД или файлам пользователей и не зависит от `ChatConsole`. Консольный пользователь,
Qt-пользователь и ADMIN могут одновременно работать с одним `chat_server`.

## Сборка и выбор интерфейса

```bash
cmake -S . -B build -DBUILD_QT_CLIENT=ON -DBUILD_TESTING=ON -DCMAKE_EXPORT_COMPILE_COMMANDS=ON
cmake --build build -j
./build/chat_server
```

В другом терминале выберите клиент:

```bash
./build/console_chat --ui console
./build/console_chat --ui qt
./build/chat_gui
./build/chat_gui --admin
```

`chat_gui` и `console_chat --ui qt` запускают одинаковое приложение. При обычном запуске
`console_chat` сохраняет консольный интерфейс. В сборке без Qt команда `--ui qt`
завершается с объяснением, как включить Qt. `BUILD_QT_CLIENT=OFF` позволяет собирать
сервер и консольный клиент без Qt. При включённой опции `console_chat` также линкуется
с Qt для выбора интерфейса в точке входа.

Qt Creator 13 может открыть корневой `CMakeLists.txt`. Выберите Kit с Qt 6.4+,
совместимым компилятором C++20 и включите `BUILD_QT_CLIENT` в CMake Configuration.
Выберите Run target `chat_gui`, Working directory — корень репозитория. Параметр
`--admin` выбирает админский вход; переключатель роли доступен и в самом окне.
В версии без тестов достаточно модуля Widgets; Qt Test и Network используются
только тестовой целью `chat_qt_tests`. Основной TCP-транспорт остаётся общим C++-кодом.

Для Qt в нестандартном каталоге укажите `-DCMAKE_PREFIX_PATH=/path/to/Qt/6.4.2/gcc_64`
или выберите соответствующий Kit. Версия Qt, указанная в About Qt Creator,
описывает сам IDE и может отличаться от Qt выбранного Kit.

## Формы Qt Designer

Разметка хранится в `src/qt/widgets/`:

| Форма | Назначение |
| --- | --- |
| `login_page.ui` | Поля входа и регистрации, сервер, порт, роль |
| `chat_page.ui` | Вкладки чатов и пользователей, история, ввод и действия ADMIN |
| `main_window.ui` | Главное окно, действия панели инструментов, контейнер страниц |
| `create_chat_dialog.ui` | Участник, имя чата и подтверждение создания |
| `ban_user_dialog.ui` | Логин, список сроков бана и подтверждение |

Откройте корневой `CMakeLists.txt` в Qt Creator, затем нужный `.ui` в режиме Design.
Главное окно не дублирует разметку страниц: `LoginPage` и `ChatPage` добавляются в
его контейнер при запуске, а редактируются в отдельных формах. Элементы для ADMIN
видны в Designer, но их доступность в приложении определяется ролью сессии.

`AUTOUIC` включён только для цели `chat_qt_ui`; Qt 6.4.2 генерирует `ui_*.h`
при сборке. В C++ локальный объект `Ui::...` вызывает `setupUi`, а виджеты остаются
дочерними объектами страницы или диалога. Приложению не нужно загружать `.ui` с диска
при запуске; дополнительный модуль UiTools не требуется.

В C++ остаются обработчики, проверка ввода, настройка динамических данных и иконок,
вкладки `QTabBar` входа/регистрации, подписи состояния в панели инструментов и строке
состояния. Отображаемые сроки бана находятся в форме, а соответствующие серверные
значения (`1d`, `10d`, `1m`, `1y`, `forever`) назначаются в `MainWindow::Moderate`.
`QMessageBox` и `QInputDialog` остаются стандартными диалогами Qt без отдельных форм.
Сохраняйте `objectName` элементов, используемых C++ и тестами. Файлы `ui_*.h` в
каталоге сборки вручную не редактируйте.

## Слои

| Слой | Ответственность |
| --- | --- |
| `app.*`, `main.cpp` | QApplication, аргументы запуска, конфиг, создание главного окна |
| `theme.*` | Оформление Qt Widgets |
| `widgets/login_page.*` | Адрес IPv4, порт, регистрация, вход и выбор роли |
| `widgets/chat_page.*` | Список чатов, полная история, черновики, список пользователей |
| `widgets/main_window.*` | Навигация, подтверждения, диалоги создания и бана |
| `widgets/*.ui` | Разметка и статические свойства виджетов для Qt Designer |
| `widgets/widget_helpers.h` | Иконки и общая проверка полей; имя без префикса `ui_`, зарезервированного AUTOUIC |
| `session_controller.*` | GUI-состояние, таймеры, очередь команд, уведомления активности |
| `client_worker.*` | Сетевые операции в одном рабочем потоке, преобразование ответов |
| `session_types.h` | Снимок сессии и данные, передаваемые сигналами |
| `ChatClient` / `TcpSocket` | Общие протокол и транспорт для всех интерфейсов |

Worker перемещён в `QThread`; операции ставятся через queued-вызовы, результаты
возвращаются сигналами. Виджеты обновляются только в GUI-потоке. Это соответствует
[модели потоков и QObject в Qt](https://doc.qt.io/qt-6/threads-qobject.html).
У `ChatClient` один владелец: рабочий поток. Одновременных запросов в одном соединении нет.
Пользовательские команды сохраняются в очереди, если в момент подтверждения диалога
ещё выполняется опрос. Таймеры не накапливают повторные фоновые задания.

При повторном создании приватного чата worker возвращает его имя сигналом
`chatAlreadyExists`. Главное окно показывает стандартный `QMessageBox::Information`
и после закрытия отправляет команду открытия чата. Диалог работает в GUI-потоке,
не останавливает фоновые обновления и закрывается при завершении сессии.

Qt-worker задаёт таймауты подключения, отправки и ожидания данных по 5 секунд.
При сетевом исключении сессия сбрасывается, окно возвращается на форму входа с причиной;
повторный вход создаёт новое соединение. Завершение окна останавливает таймеры,
запрашивает остановку потока и дожидается завершения текущей сетевой операции.
Реквизиты входа не сохраняются на диск; при выходе очищаются черновики и пароль формы.

## Возможности

| Действие | Пользователь | ADMIN |
| --- | --- | --- |
| Регистрация | Да | Нет, реквизиты задаются на сервере |
| GENERAL | Чтение и отправка | Чтение и отправка от ADMIN |
| Приватные чаты | Только свои, в том числе чат с собой | Чтение всех, отправка только в своих |
| Создание чата | С любым обычным пользователем, включая себя | С любым обычным пользователем |
| Существующий приватный чат | Информационное окно с именем; после закрытия открывается чат | Аналогично |
| Имя занято другим чатом | Предупреждение, без перехода в существующий чат | Аналогично |
| Пользователи | Список логинов с `(You)` | Логин, имя, статус и оставшееся время бана |
| Отключить / забанить / разбанить | Нет | Да |
| Удалить аккаунт | Свой, с подтверждением логина | Отдельная очистка всех вечно забаненных |

Сроки бана: день, 10 дней, месяц, год, навсегда. Вечный бан сам по себе не удаляет
аккаунт или приватные чаты. Массовое удаление — отдельная кнопка с подтверждением.
ADMIN не появляется в пользовательском списке. Участники админских чатов отображаются
с именем ADMIN, внутренний `__admin__` в UI не показывается.

Ограничения UI не заменяют серверную авторизацию: сервер проверяет команды и участников
независимо от типа клиента. Для Qt не добавлены обходные команды или отдельный админский сервер.

## Обновления и ввод

Используется существующий `config/client.conf`: `refresh_interval_ms=3000` по умолчанию.
Другой путь можно передать через `--client-config`. Qt опрашивает списки чатов,
пользователей и сообщения выбранного чата. История выводится полностью, с прокруткой;
если пользователь читает старые сообщения, обновление сохраняет положение прокрутки.
Черновики сохраняются отдельно для каждого чата до выхода из сессии. Успешная отправка
очищает поле только если пользователь ещё не изменил его содержимое.

Фоновые запросы используют `POLL` и не продлевают серверный таймаут. Нажатия клавиш,
кнопок мыши и прокрутка внутри окна отмечаются как активность и передаются через `ACTIVITY`.
Перерисовка и таймеры активности пользователя не создают. GUI не блокируется при ожидании
сети; сообщение об отключении администратором появляется при следующем запросе.

Сообщения остаются однострочными, как в существующем протоколе. Перед отображением
в QTextBrowser имена и текст экранируются: текст сообщения не становится HTML-кодом.

## Проверки

```bash
ctest --test-dir build -L qt --output-on-failure
```

Qt Test поднимает отдельный `chat_server` с временными файлами и проверяет обмен
между Qt и общим TCP-клиентом, админские права, баны и досрочный разбан, отдельную
очистку, удаление аккаунта с подтверждением, таймаут и отзывчивость GUI при зависшем сервере.
Повторное создание проверяется для пользователя, ADMIN и чата с собой: имя в
информационном окне, переход после закрытия, история, черновик и отключение во время диалога.
Коллизии имён проверяются для своих и чужих приватных чатов, ADMIN и `GENERAL`;
после предупреждения можно создать чат с другим именем.
Проверки форм покрывают значения сервера по умолчанию, регистрацию и ограничения
роли ADMIN, маскирование пароля, все пять сроков бана и отмену диалога.
Проверки виджетов запускаются через offscreen-платформу и сохраняют снимки окна
в `build/qt-screenshots/`. Пользовательские данные проекта не используются.
